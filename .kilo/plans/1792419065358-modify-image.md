# Modify Image

## Goal

Add a command-bar button `Modify image` that opens its own panel. Under the cached description, the user enters a modification request. OpenRouter edits the **current displayed image** with `meta/muse-image` (overridable in `.env`). A later request edits that result, not the file originally opened.

## Decisions

- Separate panel. Do not add this UI to Object Detection.
- Button enabled when an image is loaded. A description is optional.
- Do not write the edited image back to disk. `source_path` stays the opened file. Re-opening that file reloads the original.
- Model env: `MODEL_MODIFY_IMAGE`. Empty or missing falls back to `meta/muse-image`.
- Call `OpenRouter.images.generate` with the current image in `input_references`. (An earlier draft chose `chat.send`; `images.generate` was verified to work with `meta/muse-image`, so it was kept.)
- Send the user request, the current image as a PNG data URL, and the cached description when one exists.
- No new prompt env var. Hardcode a short edit instruction, same style as `detection.py`.
- Every OpenRouter call passes `timeout_ms=REQUEST_TIMEOUT_MS` (180 s, from `request_limits.py`) and `retries=None`. See **Request limits**.

## `modify.py`

- `DEFAULT_MODEL = "meta/muse-image"`.
- `get_modify_model()` reads `MODEL_MODIFY_IMAGE`, same empty-string fallback as `get_description_model`.
- `modify_image(image, api_key, request, description="", model=None) -> Image.Image`:
  - Encode a copy whose long side is at most 2048 (LANCZOS) as a PNG data URL. This is only the upload; it is not a second source of truth.
  - Prompt text: edit the attached image to satisfy the request and return the edited image. If `description` is non-empty, include it as context and say it may be stale after earlier edits.
  - `client.images.generate(model=..., prompt=text, input_references=[{type: "image_url", image_url: {url: data_url}}], timeout_ms=REQUEST_TIMEOUT_MS, retries=None)`.
  - Decode `response.data[0].b64_json` (raw base64 or a base64 data URL). Raise `ValueError("The model returned no image.")` when `data` is empty, and `ValueError("Could not read the returned image: ...")` when the bytes don't decode.
  - `Image.open` the bytes, `load()`, and return a detached copy.
- `modify_image_async(root, image, api_key, request, description, on_done, on_error)` — daemon thread and `root.after(0, ...)`, matching `detect_objects_async`.

## `app.py`

- Header button after Object Detection, same flat style, `text="Modify image"`, `state=tk.DISABLED`, `command=self._on_modify_image`. Place at `x=510`. Enable in `open_path` whenever an image loads. No description requirement.
- `_on_modify_image` opens a non-modal `Toplevel` titled `Modify image`, 640×520, centered like the detection panel.
  - Read-only `ScrolledText` labeled `Description (read-only):`. Insert `self.last_description` or `No description generated.`
  - Separator.
  - Label `Modification request:` and a 3-line `Text`.
  - Button `Apply`.
- On Apply:
  - Missing `OPENROUTER_API_KEY`: same error dialog as description.
  - Empty stripped request: error `Please enter a modification request.` Do not call the API.
  - If a modify request is already in flight, ignore the click.
  - Snapshot `image = self.display_master` and `description = self.last_description or ""`. Disable Apply and set its text to `Modifying...`.
  - On success, apply only if `self.display_master is image` (a newer open or edit wins). Set `self.source_image` to the returned image and `self.display_master` to `make_display_master` of it. Clear `self._detection_normalized` (boxes belong to the previous pixels). Keep `last_description`. Repaint. Clear the request field. Re-enable Apply if the panel still exists.
  - On error, show `messagebox.showerror` parented to the panel if it still exists, and re-enable Apply. Do not change the displayed image.
  - Closing the panel does not cancel the thread. A completed edit still replaces the image when the identity check passes.

## Request limits

The `openrouter` SDK builds its `httpx.Client()` without a timeout, so httpx's 5 s default applies. Its default retry policy then retries timeouts, connection errors and 5XX responses with backoff for up to 1 hour. Image edits take about 8–25 s, so without overrides every attempt timed out and was retried silently, and the panel stayed on `Modifying...` with no error. Each retry may also start a new billed generation.

- `src/transimage/request_limits.py` defines `REQUEST_TIMEOUT_MS = 180_000`.
- Every OpenRouter call (description, detection, modify) passes `timeout_ms=REQUEST_TIMEOUT_MS, retries=None`.
- A timeout or failure surfaces through `on_error` as an error dialog and re-enables the button. The user retries by clicking again.
- Any new OpenRouter call must pass the same two arguments.

## Iterative edits

The next Apply reads `self.display_master` at click time. After the first success that object is the edited image, so the next correction is applied to the current image, not `source_path`.

## Edge cases

| Case | Behaviour |
|------|-----------|
| No image | Button disabled |
| No description | Panel shows the placeholder; request still runs |
| Empty request | Error dialog, no API call |
| In-flight request | Ignore further Apply clicks |
| New file opened before callback | Drop the result |
| Older request finishes after a newer edit | Identity check drops it |
| Model returns no image | Error dialog, image unchanged |
| Request exceeds 180 s, network error, or 5XX | Error dialog after one attempt, no silent retries, image unchanged |
| Panel closed during request | Still apply the result if the same image is current |
| Detection boxes | Cleared on successful edit |

## Validation

1. `uv run pytest` — existing tests plus model fallback/override, parser cases (data URL success, missing image raises), and request limits on all three OpenRouter calls.
2. Manual: image loaded enables `Modify image` before a description exists.
3. Manual: Apply with an empty request shows an error and does not change the image.
4. Manual: a successful edit replaces the canvas and does not change the file on disk.
5. Manual: a second request edits the result of the first, not the opened file.
6. Manual: Open the same file again and the original pixels return.
7. Manual: detection boxes disappear after a successful edit.
8. Manual: a modify request on a large photo completes (about 25 s), and doesn't hang on `Modifying...`.
